Paper · §4 Methods · state space — a walk-through

How the DP took shape — every symbol explained

The story of §4's state space, now in seven acts: Tal replaced an abstract state set with an explicit grid; the notation was tidied and the neighbour set completed; the Bellman equations were rewritten "node-first"; §4.2 — the solving machinery — was reconciled with the new grid; a certificate answered is there a better speed between two nodes? (Hewitt's DDD). Then, in August: Tal flipped the recursion to cost-to-go (Part 6), and the pseudocode was consolidated into one algorithm inside a single, flat §4.2 — plus a full notation audit (Part 7). Every symbol spelled out, every formula also said in plain words.

First, the picture

The whole method lives on one flat picture — the time–distance plane:

→ across
distance d travelled along the route (0 at the start, L at the destination)
↓ down
time t elapsed since departure (0 at the start, up to the deadline T)

The ship's voyage is a line from the top-left corner (start, at distance 0, time 0) down to the right edge (arrival). Its steepness = speed: a shallow, near-horizontal stretch covers a lot of distance in little time (fast); a steep, near-vertical stretch covers little distance in a lot of time (slow). The plane is ruled by vertical lines (cell / heading boundaries in space) and horizontal lines (6-hour weather blocks in time). A decision about speed is only ever made when the line is crossed. Everything below is about turning this picture into a finite set of points a computer can search.

Part 1 · foundation

Tal's rework: an explicit discrete grid

talraviv · c0dc083 · Jul 23

The shift in one line

The old state set was abstract — "all points on the lines reachable from the start," a continuum made finite only later. Tal replaced it with an explicit grid: a concrete, listable set of points, plus a defined neighbour set for each.

1The grid

Two families of rulers cut up the plane: vertical distance lines (heading & weather-cell fixed between them) and horizontal time lines (every 6 h). Decisions happen only on a line. Tal samples each line at a fixed step:

• on a distance line, place a candidate point every τ = 0.1 h in time;
• on a time line, place a candidate point every δ = 1 NM in distance.

2The state set 𝒮

Eq. (4) — glue together two grids of points, plus the start
𝒮 = { (di − nδ, tj) : i=1…M, j=0…Θ, n=0…⌊(di−di−1)/δ⌋ } ∪
{ (di, tj − nτ) : i=0…M, j=1…Θ, n=0…⌊(tj−tj−1)/τ⌋ } ∪ { (0,0) }
reading it symbol by symbol
first { … }points sitting on the time lines tj: start at a distance line di and step back in distance by multiples of δ (n = 0, 1, 2, …).
second { … }points sitting on the distance lines di: start at a time line tj and step back in time by multiples of τ.
⌊(di−di−1)/δ⌋how many whole δ-steps fit inside the current cell — i.e. how far back you may step without leaving it.
∪ {(0,0)}add the start point explicitly.
in plain words

"List every grid point that sits on a ruler line — one family for the horizontal lines, one for the vertical lines — and throw in the start. That finite list of dots is every place the ship might ever have to make a speed decision."

3The "next line" shortcuts 𝒟(d), 𝒯(t)

𝒟(d) = argmini { i ∈ ℕ : di > d } — the index of the first distance line past d
𝒯(t) = argminj { j ∈ ℕ : tj > t } — the index of the first time line past t
in plain words

"Given where you are, which ruler line comes next?" These two just name "the next wall ahead of you" in space and in time, so the neighbour set can be written compactly.

4The neighbour set 𝒜(d,t) — time case only

Eq. (5), as Tal left it — one set
𝒜(d,t) = { (d𝒟(d), t′) : t′ = t𝒯(t) − nτ, n=0…⌊(t𝒯(t)−t𝒯(t)−1)/τ⌋ }
reading it symbol by symbol
d𝒟(d)the next distance line — the neighbours all sit on it (the ship travels forward to that wall).
t′ = t𝒯(t) − nτtheir arrival time, stepping back from the next time line by multiples of τ — i.e. every τ-slot within the current 6 h block.
in plain words

"From here, sail forward until you hit the next cell boundary. You could arrive at any of the 0.1-hour time-slots in this block — those arrival points are your neighbours." This is the time-discretised case (the arrival time is snapped to the grid). Tal did this one and asked Ami to write its mirror — the distance case — which is Part 2.

Part 3 · Jul 25 — direction later flipped (see Part 6)

The Bellman equations, node-first

amishafir · 1c6bbb4 · Jul 25

⟳ Historical note (Aug 3): the equations below minimise over predecessors — "cheapest fuel to reach this point." Tal has since flipped the recursion to cost-to-go — minimise over successors, "cheapest fuel to finish from this point." The node-first principle survives unchanged (pick the landing node, derive the speed); only the direction reversed. Current form: Part 6.

Why they had to change

Tal made the state space discrete (a grid of points + neighbour sets). But the equations that actually compute the answer still searched over a continuous range of speeds — mismatched. The fix makes them search over the discrete neighbours instead, and lets the speed fall out as a by-product. That is exactly what "node-first" means: pick the point you land on, then read the speed off it — rather than picking a speed and computing where you'd land.

1Cost-to-arrive — C*(d,t)

the recursion that fills in the cheapest fuel at every point
C*(d,t) = min(d̃,t̃) over predecessors with (d,t) ∈ 𝒜(d̃,t̃) and v̄ = (d−d̃)/(t−t̃) ∈ 𝒱
     [ C*(d̃,t̃)  +  (t − t̃) · φ(d̃,t̃; v̄) ]
with   C*(0,0) = 0.
reading it symbol by symbol
C*(d,t)the number we're solving for: the cheapest total fuel to get from the start to this point.
min(d̃,t̃)try every possible previous state (d̃,t̃) we could have arrived from, and keep the smallest total.
(d,t) ∈ 𝒜(d̃,t̃)the rule for "could have arrived from": (d,t) must be a neighbour of the candidate predecessor.
v̄ = (d−d̃)/(t−t̃)the speed of that leg = distance gained ÷ time taken. Derived, not chosen.
∈ 𝒱…and it only counts if that speed is within the allowed band (not impossibly fast or slow).
C*(d̃,t̃)the cheapest fuel to reach the predecessor (already computed).
(t − t̃)·φ(d̃,t̃;v̄)the fuel for this one leg = its duration × the fuel-burn rate in that cell at speed v̄.
in plain words

"The cheapest way to reach a point is: the cheapest way to reach some earlier point, plus the fuel to travel from there to here. So look back at every point you could have come from, work out how fast that hop was (just distance ÷ time) and what it cost, add it to the cost of getting to that earlier point, and keep the smallest answer."

The key difference from before: we no longer choose a speed. We choose which grid point we came from, and the speed is simply the slope of the straight line between them.

2Optimal speed — V*(d,t)

so we can rebuild the best plan afterwards
V*(d,t) = (d − d̃★) / (t − t̃★)   where (d̃★, t̃★) is the predecessor that won the min above
reading it symbol by symbol
(d̃★,t̃★)the winning predecessor — the one earlier point that gave the cheapest total in step 1.
(d−d̃★)/(t−t̃★)the speed of the winning leg — again just distance ÷ time.
in plain words

"Once we know the best point to have come from, the best speed is obvious: it's just the slope of the line from that point to this one." Recording it at every state lets us trace the whole optimal voyage backwards at the end, from the destination back to the start.

3What actually changed

before — search over speeds
C*(d,t) = min over v ∈ 𝒱 (a continuous range) of two hand-written cases (did the ship hit the distance line or the time line first?). You chose the speed; the landing point was computed.
after — search over neighbours
C*(d,t) = min over the discrete predecessors in 𝒜, speed v̄ = Δd/Δt derived. The two hand-written cases vanish — they're already the two halves of 𝒜. You choose the point; the speed follows.

Why this is better: it matches Tal's discrete grid exactly (finite, listable candidates rather than a continuous range), it removes the gap between a "target" speed and the speed you actually realise, and it's precisely what §4.2's arc-building algorithm already does.

strictly forward

Tal's grid 𝒮 (Eq. 4), the shortcuts 𝒟/𝒯, and the neighbour set 𝒜(d,t) (Eq. 5) are left byte-for-byte untouched — only the two equations after them changed, and they merely reference 𝒜. The "speed must be in 𝒱" rule was placed inside the new equation, precisely so Tal's Eq. (5) didn't need editing.

§4.2 "Solving the Bellman equation," reconciled with the grid

amishafir · 72033d9 · Jul 25

⟳ Historical note (Aug 4): the reconciliation below kept §4.2's four subsections and two algorithms. Both are now gone — Algorithm 2 was absorbed into a single three-stage Algorithm 1, and §4.2 was flattened to one section built around one claim. Current form: Part 7.

Why §4.2 needed surgery

§4.2 was written back when §4.1 was still abstract — so §4.2's job, at the time, was to invent the grid. After Parts 1–3, §4.1 already draws the grid and defines the neighbours. That left §4.2 doing two bad things: re-deriving what §4.1 had just done, and in places claiming things that are no longer true (its opening literally said the state set "has to be made finite" — but Eq. (4) is already a finite list). Four fixes follow — none of them touches a single character of §4.1.

1A new job description (the intro)

before
"…the state set 𝒮 of Eq. (4) has to be made not merely finite but of tractable size. Second, 𝒮 and the speed transitions between its states have to be enumerated…"
after
"Eqs. (4)–(5) already define the state grid 𝒮 and its admissible successors 𝒜(d,t)… Three things remain: bound the size, enumerate only the reachable states and admissible arcs, and sweep the recursion."
in plain words

"The map is already drawn — §4.1 drew it. What's left for §4.2 is bookkeeping: count how big the map is, walk only the part of it a real voyage can touch, and solve on what the walk found." The old opening set §4.2 the task of creating the map — a job that no longer exists.

2§4.2.1: from "create the grid" to "use the grid"

The old first paragraph argued: "speeds are continuous → infinitely many reachable points → we contain this by discretising." That was the motivation for inventing the grid. Now the paragraph says the grid is fixed by Eq. (4), and keeps the old argument only as a one-line aside explaining why the grid lives on the lines (any per-speed discretisation would explode as Klines; per-line grids stay polynomial).

Two things in this subsection are still genuinely needed, and both were kept — just recast:

what stays, and its new role
⟨x⟩δ, ⟨·⟩τthe snap operators — no longer "how the discretisation is created," now simply the rounding arithmetic the enumeration uses to land arrivals exactly on §4.1's grid dots (round a landing distance to the nearest 1 NM, a landing time to the nearest 0.1 h).
|𝒮| boundnow read directly off Eq. (4) by counting: each distance line holds at most ⌈T/τ⌉ dots, each time line at most ⌈L/δ⌉ dots → |𝒮| = O(M·T/τ + Θ·L/δ), and |𝒜| = O(K·|𝒮|).
in plain words

"How big is the search? Count dots per ruler, times the number of rulers. A distance line can hold at most one dot per 0.1 h of the voyage; a time line at most one dot per mile of the route. Multiply out and the whole thing is comfortably polynomial — no exponential blow-up anywhere."

3§4.2.2: one name per thing, and an honest claim

(a) Duplicate definition removed. §4.2 used to re-define "the next line ahead" from scratch (d̄(d) = min{di > d}) — the very thing Tal's 𝒟(d), 𝒯(t) already do. Now the bars are declared as shorthand: d̄(d) ≡ d𝒟(d), t̄(t) ≡ t𝒯(t). One concept, one definition, two spellings.

(b) The dots are joined out loud. A new sentence states what was previously only implicit:

"Together the two ranges enumerate exactly the neighbours 𝒜(d,t) of Eq. (5) whose realised speed is admissible (v̄ ∈ 𝒱) — the same set over which the recursion of Eq. (cost-to-arrive) minimises."
in plain words

"The algorithm's candidate list and the equation's candidate list are literally the same set — the text now says so, instead of leaving the reader to check it."

(c) An overclaim corrected. The old text said the forward walk "discovers exactly the … set 𝒮 of Eq. (4)." But Eq. (4) lists every dot that could exist; the walk from the start only visits the dots a real voyage can touch — far fewer. Fixed to: "…discovers exactly the subset of the grid 𝒮 reachable from the origin — typically a small fraction of the full grid."

why the distinction matters

It's the difference between "every square on the chessboard" and "the squares a knight starting at a corner can actually reach in the moves available." A careful reviewer would have flagged the old sentence; and the gap is also exactly why the enumeration is cheap in practice.

4Algorithm 1: the code points at the formula

The algorithm's two enumeration loops now carry annotations naming which half of Eq. (5) each one builds:

loop 1"distance line binds: enumerate arrival times — the first set of Eq. (5)" (Tal's time case).
loop 2"time line binds: enumerate arrival distances — the second set of Eq. (5)" (the added distance case).
in plain words

"The pseudocode and the formula now point at each other: read a loop, and it tells you exactly which piece of the neighbour set it is constructing."

Part 5 · the certificate question

Is there a better speed between two nodes?

T25–T26 + experiment E1–E3 · Jul 28 · docs/ddd_experiment_plan.md

The question the grid leaves open

The DP only ever considers the grid dots. The true optimum F* may cross a line between two dots, at a speed we never tried. We cannot compute F* — but we can bracket it: our plan is an upper bound (F* ≤ FDP — ours is a real, sailable plan), and a deliberately-too-optimistic model gives a lower bound (LB ≤ F*). Then FDP − LB certifies the gap, no matter where F* hides. The question is how to build a good LB.

1The method: Dynamic Discretization Discovery (DDD)

Who: Michael Hewitt (Editor-in-Chief of Transportation Science, Loyola Chicago), with Natashia Boland & Martin Savelsbergh — Operations Research 2017 (the founding paper), Transportation Science 2021 (interval-based), and the companion study literally titled “The price of discretizing time.”

The problem they solve: decisions live in continuous time, but the solvable model is a time-expanded network on discrete nodes — the optimum may fall between the nodes. Sound familiar? Their answer is an iterative bracket:

the DDD loop, step by step
① relaxbuild a small, partial grid whose model is provably too optimistic — every arc is allowed to arrive a little earlier than physics permits (rounded down to an existing point). Any real plan has a cheaper-or-equal shadow in this model ⇒ its optimum is a rigorous LB.
② repairtake the LB solution and try to make its timings real. If they already are — it IS the continuous optimum. If not, the repaired schedule is a feasible UB.
③ refineadd exactly the missing grid points where the relaxation cheated — nowhere else.
④ repeatLB rises, UB falls; converges to the continuous optimum with a certificate at every step — typically on <1 % of the full grid.
in plain words

“Don’t ask is my grid fine enough? Build a deliberately generous small model whose answer can only be better than reality, hold it against your real plan, and squeeze. Where the squeeze doesn’t close, that’s exactly where the grid needs another point.”

2Applying it to our problem — three experiments

Our 𝒮 (δ = 1 NM, τ = 0.1 h) is the “full expansion” DDD avoids, and FDP is the feasible UB. We ran three probes (code: pipeline/dp_rebuild/ddd_lb.py):

E1 · grid sensitivity (empirical, not a certificate)

Re-solve with the grid halved and doubled. Fuel moves by only ~0.07–0.08 % under halving (0.3–0.5 % under doubling) — but non-monotonically: the finer grid can come out slightly above the paper grid, because the arc sets aren’t nested (glide-past corners, band-edge rounding). Moral: extrapolating from grid refinement is unreliable here — a genuine certificate is needed, which is exactly DDD’s point.

E2 · the local node-slide certificate (rigorous, and ours)

Take the optimal plan. Pick any interior decision point; slide it continuously along its mandatory line — off the grid — keeping its neighbours fixed, speeds in 𝒱, weather exactly as the DP sees it; re-optimise its two legs (golden search). The gain says how much that one between-the-nodes freedom was worth.

the certificate equation — Eq. (10) of the paper (eq:slide, §4.3)
g(qk) = [ f(qk−1, qk) + f(qk, qk+1) ] − minq′ ∈ ℓ(qk) [ f(qk−1, q′) + f(q′, qk+1) ]
reading Eq. (10) symbol by symbol
q0 … qnthe decision points of the optimal schedule — the chain the DP produced. q0 = departure, qn = arrival; both stay fixed.
qkthe interior point being tested — one knot of the rope, sitting on its mandatory line (a cell boundary or a 6-h line).
qk−1, qk+1its plan-neighbours — the previous and next decision points, held fixed while qk is tested.
ℓ(qk)the slide domain: the piece of qk's line between its two neighbours. Continuous — it sweeps through and between all the grid dots. (Not bounded by the nearest dots!)
q′a candidate off-grid position on ℓ(qk) — "what if the decision had been made here instead?"
f(a, b)leg fuel from a to b: φ(a; v̄)·Δt with the speed derived, v̄ = Δd/Δt — and set to ∞ if v̄ leaves the band 𝒱 (an illegal leg can never win the min). Same φ conventions as the DP, so the comparison is apples-to-apples.
min over q′a 1-D continuous minimisation along the segment (golden-section search) — both incident legs re-optimised together, since moving q′ changes both speeds at once.
g(qk)the gain: today's two-leg cost minus the best achievable with qk anywhere on its line. Always ≥ 0 (the current position is itself a candidate). g(qk) = 0 means the grid dot was already the continuum's choice.
in plain words — Eq. (10)

"Take one knot of the rope. Ask: if this knot could sit anywhere along its rail — not just on the grid — how much fuel would the two ropes tied to it save at best? That number is g. Summing g over all knots (one sweep) bounds what one round of off-grid freedom is worth; applying the winning positions and re-sweeping to convergence measures it exactly: 0.17–0.87 %."

in plain words

“Wiggle every knot of the rope, one at a time, anywhere along its rail. No knot wants to move more than a hair — the biggest single gain anywhere is ~0.1 mt, and even letting every knot settle (iterated polish) recovers only a fraction of a percent.” Full mechanics — and why this is not DDD — in block ③ below.

E3 · the global interval LB (DDD proper — honest verdict)

We built the real thing: intervals on the rectangle edges, each arc costed at the minimum fuel over its whole transition family, shortest path ⇒ rigorous LB; then DDD-style bisection along the LB path, plus a Lagrangian price on time. It is sound and monotone (LB 66 → 76 mt in seconds) but converged to only ~38 % of FDP: the family-min lets the relaxed vessel “re-enter each box at its best corner,” harvesting free distance per hop — and pricing time doesn’t stop the teleporting. Fixing that positional leak is the actual substance of the DDD papers. Verdict: future work (and a nice research direction), not a paper claim.

3Inside the §4.3 certificate — and why it is not DDD

The certificate’s engine is iterated continuous polish (coordinate descent). The exact mechanics, step by step:

the loop, precisely
DP — oncethe expensive machinery (1.2M-arc graph, Bellman sweep) runs one time, giving the grid-optimal plan. After that the graph is discarded — all that remains is the chain of ~200 decision points.
slide domaina point slides between its plan-neighbours p and r along its mandatory line — not between the nearest grid dots. The grid plays no role; the point may settle anywhere in the continuum.
no speed searchspeed is never chosen — moving the point re-tunes both incident legs’ speeds at once, as v̄ = Δd/Δt to the fixed neighbours (node-first, carried into the continuum; v̄ ∈ 𝒱 enforced).
apply on the flyan improving move is applied immediately (Gauss–Seidel): the very next point is optimised against the already-moved neighbour. Forward knowledge flows within the sweep; the backward reaction (the previous point re-adjusting) waits for the next sweep.
sweep, repeateach move re-opens its neighbours, so improvements ripple along the chain; sweeps repeat until a full pass gains < 0.001 mt. Convergence is guaranteed: fuel falls monotonically and is bounded below — in practice 6–20 sweeps.
fixed backbonethe order of lines crossed (which cells, in which weather blocks) never changes — only the crossing coordinates move. A better backbone is invisible to this process.
DP (once) → chain of points → sweep, sweep, sweep … → F stops moving
F*  ≤  Fpolished  ≤  FDP — the result is a tighter UPPER bound on the continuous optimum, never a lower bound.
what this is NOT — DDD
DDD is top-down and global: it never starts from a solution. It builds a deliberately optimistic sparse model whose optimum is a lower bound on every possible plan at once, then refines where the optimism was used. That global LB is exactly what the polish cannot provide (our E3 attempt stayed loose) — and is the future-work line of §4.3.
what this IS — local polish
Bottom-up and local: start from the finished plan, let each decision point roam the continuum one at a time, keep every improvement, converge. It proves the plan is locally optimal in the continuum — no single off-grid repositioning helps — and measures the continuum’s local worth: 0.17–0.87 %.
in plain words

The polish perfects reality; DDD brackets possibility. §4.3 does the first and cites the second as its lineage — the paper says “in the spirit of” the bracketing methods, and explicitly leaves the global certificate to future work. Never present §4.3 as an implementation of DDD.

Part 6 · Tal's flip (Aug 3)

The Bellman equation turns around: cost-to-go

talraviv · c4f513c · Aug 3 — plus Ami's completion of the pass, 8b4cbaa · Aug 4

The shift in one line

Same node-first idea, opposite direction. Part 3's recursion asked "what is the cheapest way to reach this point?" and looked backwards at predecessors. Tal's version asks "what is the cheapest way to finish the voyage from this point?" and looks forwards at successors. Three things get nicer at once: the min ranges over 𝒜(d,t) itself (Tal's own Eq. 5 — no awkward "states whose neighbour I am"), V*(d,t) becomes the outgoing speed — a genuine control policy — and the final answer sits at the start: F* = C*(0,0).

1The recursion, as it now stands in the paper — Eq. (6)

cost-to-go: min over successors, two cases
C*(d,t) = min(d̃,t̃) ∈ 𝒜(d,t)
     {  ∞ if t̃ = tΘ , d < dM
        C*(d̃,t̃) + (t̃ − t) · φ(d,t; (d̃−d)/(t̃−t)) otherwise }
boundary: C*(dM, t) = 0 for every reachable (dM,t), t ≤ T  ⇒  F* = C*(0,0)
reading it symbol by symbol
min over 𝒜(d,t)try every successor — every grid node reachable from here in one leg (Tal's Eq. 5, which now carries the v̄ ∈ 𝒱 condition inside it, and measures its ranges from the current point).
∞ case"if that leg lands on the final time line without the voyage being done — dead end, price it infinite." The deadline is enforced inside the recursion. Audit flag A1: as written the condition says d < dM (the source), which is true for every non-sink state — it would also kill a perfectly legal arrival at (L,T). The intended condition is d̃ < dM (the successor). One tilde; flagged for Tal.
(t̃−t)·φ(d,t;·)the fuel of the outgoing leg: duration × burn rate. The rate is evaluated at the source (d,t) — the source fixes which cell and which weather block the leg lives in. Matches the code exactly.
(d̃−d)/(t̃−t)the leg speed — still derived, never chosen. Node-first survived the flip untouched.
C*(dM,·) = 0the seed: standing at the destination costs nothing more. (Replaced the old C*(0,0)=0, which anchored the to-arrive version.)
in plain words

"The value of a point is: the cheapest way to finish the voyage from any point you can jump to next, plus the fuel of that jump. Plan the voyage from the finish backwards — and then the number written at the start point is the answer."

2The optimal speed is now a policy — Eq. (7)

V*(d,t) = (d̃★ − d) / (t̃★ − t)   where (d̃★, t̃★) is the successor that won the min
in plain words

"Stand at any grid point and V* tells you what to do next — the slope of the best outgoing leg. Because every state carries one, the DP hands back a full policy, not just one path: recover the plan by walking forward from (0,0), successor to successor." (The old version recorded the incoming leg and back-tracked from the destination.)

Build + discretise + price in one pass; solve with one sweep

1The consolidated Algorithm 1 — sixteen numbered lines, three stages

Input: lines d₀…d_M=L, t₀…t_Θ=T · band [v_min,v_max] · snaps δ,τ · FCR φ Output: speed schedule and total fuel consumption ▷ Stage 1 — forward closure: discover the reachable states and price every arc 1𝒮←{(0,0)}; 𝒜←∅; queue Q←[(0,0)] 2while Q not empty do 3 (d,t)←pop(Q); if d=L or t=T then continue 4 C ← 𝒜(d,t) of Eq.(5) ▷ v̄∈𝒱 built in; glide rule if the wall is τ-unresolvable 5 for (d̃,t̃) ∈ C do 6 v̄←(d̃−d)/(t̃−t); if v̄ unattainable at (d,t) then continue 7 𝒜 ← 𝒜 ∪ {(d,t)→(d̃,t̃) with speed v̄, cost φ(d,t;v̄)·(t̃−t)} 8 if (d̃,t̃)∉𝒮 then 𝒮←𝒮∪{(d̃,t̃)}; push(Q,(d̃,t̃)) 9 end for 10end while ▷ Stage 2 — backpropagation: Eq.(6) once per state, every successor already valued 11C*(s)←+∞ ∀s∈𝒮; C*(L,t)←0 for every (L,t)∈𝒮 12for each (d,t)∈𝒮 in reverse lexicographic (t,d) order do 13 C*(d,t) ← min over arcs [ φ(d,t;v̄)·(t̃−t) + C*(d̃,t̃) ]; record (d̃★,t̃★) 14end for ▷ Stage 3 — extraction 15F* ← C*(0,0); walk (0,0)→(d̃★,t̃★)→⋯ until d=L, emitting V*(d,t) 16return F* and the speed schedule
why each stage is what it is
Stage 1 = 3-in-1Discovering the reachable states, discretising them, and pricing every arc are one step, not three. Each node Eq. (5) emits arrives already on the grid (no post-hoc snapping), already carrying its speed v̄ = Δd/Δt, and already priced — φ evaluated on the spot. When the loop empties, the graph is fully priced; the expensive physics (one still-water-speed inversion + FCR per arc) has been paid exactly once per arc.
Stage 2 = 1 sweepCost-to-go needs successors valued before their sources — so sweep in reverse lexicographic (t,d) order. Valid because every arc strictly increases both coordinates (DAG). Seed C*(L,·)=0; dead ends inherit ∞ from the initialisation — the ∞ case of Eq. (6) needs no test. One min per state; no priority queue, no iteration.
Stage 3 = 2 linesExactly what Tal asked for: F* = C*(0,0), then walk forward reading V* at each stop. Algorithm 2 no longer exists — its job dissolved into Stages 2–3.
in plain words

"The forward pass lays the pipes and fills them; the backward pass just reads the meters, back-to-front; the last two lines print the bill and the route."
